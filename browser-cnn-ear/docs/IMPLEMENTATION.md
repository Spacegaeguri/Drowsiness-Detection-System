# 구현 설명

## 기존 얼굴 모델과의 관계

기존 루트 노트북은 DDD 얼굴 데이터, 128×128 RGB, MobileNetV2 전이학습을 사용합니다. 기존 `Drowsiness-System/` 노트북에는 128×128 얼굴 입력의 일반 CNN이 있습니다. 이 폴더는 MRL 눈 이미지, 64×64 RGB, 직접 구성한 작은 CNN을 사용하는 별도 구현입니다. 라벨 0은 감긴 눈, 1은 열린 눈이며 얼굴 전체의 졸음 라벨과 동일한 문제가 아닙니다.

## 학습과 브라우저 실행

```text
MRL 눈 이미지 → TensorFlow 데이터 로딩 → Keras CNN 학습
                                       ↓
                              best_eye_model.keras
                                       ↓
                              TensorFlow.js 변환
                                       ↓
                          model.json + 가중치 shard

웹캠 → MediaPipe 눈 좌표 → 좌우 눈 crop → 64×64 → CNN 점수
                       └→ EAR 계산          ↓
                                     CNN + EAR 규칙
                                           ↓
                                 각 눈의 최근 결과 보정
                                           ↓
                                  양쪽 눈 CLOSED 2초
                                           ↓
                                  SLEEPING + Web Audio
```

CNN은 Rescaling(1/255), Conv2D 32·64·128 + MaxPooling 세 단계, GlobalAveragePooling, Dense 64, Dropout 0.4, Dense 1 + sigmoid로 구성합니다. 학습 파라미터는 101,569개이고 float32 가중치는 406,276바이트입니다. `.keras` 파일은 옵티마이저 상태 등도 포함해 이보다 큽니다. Keras는 레이어 구성·학습 API, TensorFlow는 데이터 처리 및 실제 수치 연산, TensorFlow.js는 웹 추론에 사용합니다.

웹 `predictEye()`는 0~255 픽셀을 모델에 그대로 전달합니다. 정규화가 이미 모델 내부 Rescaling에 있으므로 외부에서 다시 255로 나누면 안 됩니다.

## EAR

두 가로 끝점을 `h1`, `h2`, 두 세로 쌍을 `(v1a, v1b)`, `(v2a, v2b)`라고 하면:

```text
EAR = (distance(v1a, v1b) + distance(v2a, v2b))
      / (2 × distance(h1, h2))
```

실제 배열은 왼쪽 `[33, 133, 159, 145, 158, 153]`, 오른쪽 `[362, 263, 386, 374, 385, 380]`입니다. 흔히 도식에서 쓰는 p1~p6의 시계방향 배열과 순서가 다릅니다. 원본은 MediaPipe의 정규화 x·y 좌표를 그대로 계산합니다. 가로·세로 정규화 척도가 다른 비정사각형 영상에서는 픽셀 좌표로 계산한 EAR과 다를 수 있습니다. 이 가져오기에서는 결과를 보존하기 위해 계산식을 바꾸지 않았습니다. 향후 픽셀 좌표로 바꾸면 기존 임계값도 재검증해야 합니다.

## 한쪽 눈의 실제 분기

`openScore >= 0.55`이면 CNN 기본 판정 OPEN, 그렇지 않으면 CLOSED입니다. 감긴 눈 점수는 `1 - openScore`입니다.

| 우선순위 | 조건 | 출력 |
| --- | --- | --- |
| 1 | EAR < 0.15 | CLOSED |
| 2 | CNN 기본 CLOSED 및 EAR < 0.18 | CLOSED |
| 3 | CNN 기본 CLOSED 및 감긴 눈 점수 >= 0.85 | CLOSED |
| 4 | 나머지 | OPEN |

EAR 0.30·openScore 0.40은 CNN 기본 CLOSED여도 결합 출력 OPEN입니다. EAR 0.30·openScore 0.10은 감긴 눈 점수 0.90이므로 CLOSED입니다. EAR 0.14·openScore 0.90은 1번 규칙에 의해 CLOSED입니다.

이 규칙은 과거 상태에 따라 개폐 임계값을 다르게 적용하는 정식 히스테리시스가 아니라, 현재 CNN·EAR 값에 대한 여러 분기입니다. 시간 방향 흔들림 억제는 다음 단계의 기록 보정이 담당합니다.

## 보정·시간·경고

- 각 눈의 결과 배열을 최대 5개 유지합니다.
- `CLOSED 수 / 현재 배열 길이 >= 0.6`이면 보정 결과 CLOSED입니다. 처음 1~4개 결과에도 즉시 적용합니다.
- 두 눈의 보정 결과가 모두 CLOSED가 되는 순간 `performance.now()`로 타이머를 시작합니다.
- 관측된 처리 프레임에서 이 상태가 유지되어 2초가 지나면 SLEEPING입니다. 어느 한쪽 보정 결과가 OPEN이면 타이머 초기화·알람 중지·AWAKE입니다.
- 소리는 900Hz 사인파 0.25초이며, 알람 시작 즉시 한 번과 이후 700ms 간격으로 반복합니다.
- 코드는 `requestAnimationFrame()`으로 분석합니다. 센서의 서로 다른 프레임만 처리하는 검사나 탭 중단 후 시간 공백 게이트는 없습니다. 5개가 고정 시간 길이를 뜻하지 않으며 실차용 연속 관측 보장을 추가 검증해야 합니다.

## 오류와 한계

모델 로딩 동안 시작 버튼을 잠급니다. 얼굴 미검출 시 기록·타이머·알람을 초기화합니다. 카메라 오류는 버튼을 다시 활성화하고, 처리 오류는 분석과 알람을 중지합니다. 처리 오류 후 재시작 UI는 없으므로 페이지를 새로고침해야 합니다.

`numFaces: 1`로 설정되어 한 명을 대상으로 합니다. 프레임별 최종 결과는 실제 눈 상태의 추정값이므로 실제로 눈을 뜬 순간과 보정 결과가 OPEN으로 바뀌는 순간에는 짧은 차이가 날 수 있습니다. 작은/잘못된 crop은 `openScore = 1.0`을 반환하며, 가로 거리가 0인 EAR은 0을 반환합니다. 이 값들은 미검출을 정교하게 다루는 별도 유효성 신호가 아니므로 향후 보완 대상입니다.

조명·안경·각도·카메라 해상도와 화면 비율에 대한 독립 검증, 개인별 보정, 하품·고개 움직임 감지는 추가 과제입니다.
